# Task 02 - Seeded perfect maze generation and wall segments

**Depends on:** 01. **Unblocks:** 05.

## Goal

When this is done, `src/maze.js` produces a solvable perfect maze of any size from a seed, and
converts it into a flat list of wall line segments in cell units that collision and rendering both
consume. Same seed always gives the same maze, which is what makes every later test assertable.

## Spec first

Fill in the `SPEC.md` **Coordinate model** and **Maze generation** sections.

- Coordinate model: the maze is `cols` x `rows` cells, origin top-left, each cell 1.0 x 1.0. Cell
  `(c, r)` has centre `(c + 0.5, r + 0.5)`. All game state is in cell units; pixels exist only in the
  renderer.
- Start is cell `(0, 0)`. Exit is cell `(cols - 1, rows - 1)`.
- The maze is a **perfect maze**: exactly one path between any two cells, no loops, no isolated
  cells. Generated by a recursive backtracker (depth-first carve with a randomized neighbour order)
  driven by a seeded RNG.
- The outer border is always solid wall. There is no entrance gap and no exit gap; start and exit are
  interior cells.
- Walls are line segments on cell boundaries, given as `{ x1, y1, x2, y2 }` in cell units. Each
  boundary is emitted exactly once, so a wall shared by two cells is not duplicated.

## Failing tests first

Write `tests/maze.test.js` before `src/rng.js` and `src/maze.js` exist. Expected red run:

**RNG**

| Test case | Assertion |
| --- | --- |
| `mulberry32 is deterministic` | Two generators from seed `12345` yield identical first 100 values. |
| `mulberry32 differs by seed` | Seeds `1` and `2` yield different first values. |
| `mulberry32 stays in range` | 1000 draws are all `>= 0` and `< 1`. |

**Generation**

| Test case | Assertion |
| --- | --- |
| `generate is deterministic for a seed` | `generate(8, 8, mulberry32(42))` twice deep-equals itself. |
| `generate is a perfect maze` | Carved passage count equals `cols * rows - 1` (tree property, no loops). |
| `every cell is reachable` | Flood fill from `(0,0)` across carved passages visits all `cols * rows` cells. |
| `border is always solid` | No cell on the outer ring has a carved passage leading outside the grid. |
| `solve finds a start-to-exit path` | `solve(maze)` returns a path whose first element is `(0,0)`, last is `(cols-1, rows-1)`, and where every consecutive pair is orthogonally adjacent with a carved passage between them. |
| `solve path has no repeats` | The returned path visits no cell twice. |
| `rejects degenerate sizes` | `generate(0, 5, rng)` and `generate(5, 0, rng)` throw. A 1x1 maze is valid and yields only border walls. |

**Segments**

| Test case | Assertion |
| --- | --- |
| `toSegments emits the outer border` | The four border segments (or their subdivided pieces) are present for a 1x1 maze, and no others. |
| `toSegments has no duplicates` | No two segments are equal, and no segment is the reverse of another. |
| `toSegments coordinates are in cell units` | Every coordinate is an integer in `[0, cols]` for x and `[0, rows]` for y. |
| `segment count matches wall count` | For a perfect maze, total boundary count minus carved passages equals `segments.length` (with unsubdivided per-cell-edge segments). |
| `carved passages have no segment` | For a maze where `(0,0)`-`(1,0)` is carved, no segment lies on the shared edge `x=1, y in [0,1]`. |

## Implementation outline

**`src/rng.js`**

```js
export function mulberry32(seed) { /* returns () => float in [0,1) */ }
```

Standard mulberry32. Keep it exactly as published so behavior is stable across Node versions.

**`src/maze.js`**

```js
export function generate(cols, rows, rng)   // -> { cols, rows, passages }
export function toSegments(maze)            // -> [{ x1, y1, x2, y2 }]
export function solve(maze)                 // -> [{ c, r }] start to exit
```

- Represent carved passages as a `Set` of canonical keys, e.g. `"c,r|c2,r2"` with the
  lexicographically smaller cell first. This makes "is this boundary open" an O(1) lookup and makes
  the no-duplicate-segment property fall out naturally.
- Recursive backtracker: iterative stack to avoid blowing the call stack on a 24x24 grid. At each
  cell, shuffle the four neighbours using `rng` (Fisher-Yates with `rng`), visit unvisited ones,
  carve the passage on the way in.
- `toSegments`: for every cell, emit its top edge if the neighbour above is absent or unconnected,
  and its left edge likewise; then emit the right edge for the last column and the bottom edge for
  the last row. This visits each boundary exactly once.
- `solve`: BFS over carved passages from `(0,0)`, reconstruct via parent map. Used by tests and
  potentially by a debug key later, not by gameplay.

Keep all three functions pure. `generate` takes the `rng` function rather than a seed so callers
choose the seed policy.
